1. **Phase 1 (beta.37) — safe fixes plus Lucid TV reliability.** Trailer playback behind detail child pages, `bingeGroup` badge matching, Home-row sync data loss, Multi-view networking parity, bounded Multi-view / Live TV retries, and the Lucid TV pause/advance/recovery bugs behind “the channel paused and never moved on”.

## 2. Guardrails

1. **Never merge or rebase** upstream/forks. Port individual hunks only.
2. **One branch per phase, one commit per item**, each independently revertable.
3. **No dependency upgrades** in this plan (Gradle, AGP, Kotlin, Compose, media3, Ktor, OkHttp stay put).
4. Every pure helper gets a unit test. UI changes get a device smoke test.
5. Behaviour changes go behind an existing setting or a new toggle; defaults must preserve today's behaviour unless the change is a clear bug fix.
6. No database migrations. The guide DB, profiles and sync shapes stay untouched.
7. Build gate per phase: `:app:testFullDebugUnitTest` + `:app:assembleFullDebug` on **JDK 17** (the current shell has JDK 11 — see §9).
8. Release only after install-over-previous check. Version bumps are separate commits.

**Definition of done for every item**

- Compiles with no new warnings in touched files.
- New unit tests pass.
- Manual case from the acceptance line passes on a TV target.
- No change to a default path unless listed in the item.
- Commit message names the report source (SHA/issue).

### 1.4 Multi-view networking parity: VPN, redirects, timeouts — M (3–4 h)

- **Source:** local audit against `LiveTvPlaybackController` / `PlayerPlaybackNetworking`
- **Files:** `app/src/main/java/com/nuvio/tv/livetv/multiview/LiveTvMultiViewScreen.kt`

### 1.5 Bounded Multi-view retry + backup fallback — M (6–8 h)

- **Source:** NuvioPlusIPTV-Mobile [`9cc15f22`](https://github.com/homelessbrian/NuvioPlusIPTV-Mobile/commit/9cc15f22afc4a15708e522ee9b3924c6ad96968d), [`7252e578`](https://github.com/homelessbrian/NuvioPlusIPTV-Mobile/commit/7252e5782a0b23de8f6b23aca6850c1247cef31d)
- **Files:** `LiveTvMultiViewScreen.kt`, `MultiViewRepository.kt`, new `MultiViewRetryPolicy.kt` + test, `LiveTvViewModel.kt` (read-only use of `backupsFor`)
- **Local evidence:** `MultiViewPane` flags `failed`, waits 2 s, increments `autoReload`, and rebuilds. A refused/dead URL repeats this roughly every 4 s indefinitely and holds a decoder + sockets. The label stays “Retrying…” across every rebuild, so it never shows an attempt count or that it gave up.
- **Change:**
  1. Add a pure `MultiViewRetryPolicy`: attempts 1–5, delays `2s, 4s, 8s, 15s, 30s`, stop after 5; `shouldTryBackup(attempt, autoBackupChannel)` at attempt ≥ 2.
  2. Track `retryAttempt`; reset it on `STATE_READY` plus real position progress. Do not count a user pause (already skipped).
  3. After the cap, stop rebuilding and show **“Stream unavailable · hold OK for Refresh”**. The pane menu's Refresh resets the counter.
  4. When `settings.autoBackupChannel` is on and the cap is reached, ask the screen for the next copy: `viewModel.backupsFor(channel)` → skip keys already in the grid → `MultiViewRepository.replace(id, newStream)`; show `LiveTvNotice` “Switched to backup: …”. If none, keep the unavailable state.
  5. Add `MultiViewRepository.replace(id, stream)` and keep `id` stable so focus/layout do not jump.
- **Acceptance:** dead primary URL → at most 5 rebuilds with growing delay, then a stable message; with a working backup and the setting on → one automatic switch and normal playback; pausing a pane never triggers a retry; removing/re-adding resets state.
- **Test:** `MultiViewRetryPolicyTest`; device test with a playlist whose first copy is a dead URL.
- **Risk:** 🟡 medium (player + focus). **Rollback:** keep the policy but disable backup switching first; revert commit last.

### 1.6 Live TV: stop re-asking a refused stream — M (4–6 h)

- **Source:** TuvoraMobile [`3772c239`](https://github.com/paradox-kush/TuvoraMobile/commit/3772c239fdabd30feb69174b979521a25ae3aa7e); cross-app opportunity in the Nov 19 report
- **Files:** `app/src/main/java/com/nuvio/tv/livetv/player/LiveTvPlaybackController.kt`, new `LivePlaybackRetryPolicy.kt` + test
- **Local evidence:** `describe()` already turns HTTP 401/403/404/429/456/458/509 into plain-language reasons, but `scheduleReconnect()` ignores that classification and runs up to `MAX_RECONNECTS = 8` with 2–10 s delays for every error.
- **Change:**
  1. Pure policy: `isProviderRefusal(status)` (401, 403, 404, 410, 429, 456, 458, 509) and `retryDelayMs(attempt, refusal)`.
  2. Provider refusals: no freeze-ladder loop. Do at most **one** delayed retry for 429/456/458/509, then stop and show the existing message plus **OK to retry**. 401/403/404/410 stop immediately.
  3. Keep the existing `attempt == 2` backup/game-failover check so a working copy can still take over.
  4. Network/timeout/parse errors keep the current bounded exponential retry.
  5. `Retry` clears the counter and starts fresh.
- **Acceptance:** simulated HTTP 458/429 produces at most one retry and a stable “Too many connections” message; HTTP 403 stops immediately; pulling the network still retries and recovers; backup switching still happens when enabled.
- **Test:** `LivePlaybackRetryPolicyTest` (status codes, delays); device test by pointing a channel at a 403/458 test URL.
- **Risk:** 🟡 medium (Live TV playback). **Rollback:** feature-flag the policy with a constant, then revert.

### 1.7 Lucid TV: internal player changes must not count as “user paused” — S (2–3 h)

- **Source:** owner report 2026-11-19 (“channels are pausing and not restarting”); local audit
- **Files:** `LiveTvPlaybackController.kt`, `LiveTvPlayerScreen.kt`, new `LivePauseState.kt` + test if useful
- **Local evidence:** `onPlayWhenReadyChanged()` does `_state.value = copy(userPaused = !playWhenReady)`. Internal changes — background pause, audio-focus loss, some reloads — also flip `playWhenReady`, so `userPaused` can become true without the viewer pressing pause. `scheduleVirtualAdvance()` waits while `userPaused`, so the Lucid clock can stop permanently; the UI also shows the wrong pause state.
- **Change:** make `userPaused` **user intent only**:
  - set it in `togglePause()` (and clear it in `play()` when a new item starts);
  - stop deriving it from `onPlayWhenReadyChanged()`; keep `isPlaying` separate;
  - keep `pausedForBackground` separate and never let it block the advance clock.
- **Acceptance:** a forced reload or app background/foreground does not leave `userPaused=true`; after a failed reload the next EPG item still starts; the Play/Pause key still pauses and resumes; the UI pause icon matches reality.
- **Test:** pure `LivePauseState` transition test; device pause/reload/background pass.
- **Risk:** 🟡 medium-low. **Rollback:** one state assignment + one callback body.

### 1.8 Lucid TV: pause a film as VOD, not as a live pause buffer — S–M (2–4 h)

- **Source:** owner report; local audit
- **Files:** `LiveTvPlaybackController.kt`, `LiveTvPlayerScreen.kt`
- **Local evidence:** `togglePause()` sends any non-catch-up channel to `pauseLive()`. For a Lucid VOD slot (`activeVirtual != null`, `catchupTitle == null`, `_ownTimeline == false`) that starts a timeshift recording, calls `p.stop()`, and replaces the film with a live-style buffer. Resume then goes through the shift path, which can leave the film stopped and the queue clock out of step.
- **Change:**
  1. In `togglePause()` and `pauseLive()`, if the active tune is a Lucid VOD item (`!live && !relay`), use a plain `p.pause()` / `p.play()` and keep the position.
  2. Never start a pause buffer for a Lucid VOD item.
  3. Expose `virtualVod`, `virtualTitle` and `virtualEndsAtMs` in `LivePlaybackState` so the player UI can render a normal VOD seek bar (UI work is 4.6).
- **Acceptance:** pause at 20:00, wait 30 s, resume → still at 20:00; no “Pause buffer” entry in the start-up report; pause/resume five times does not break the advance clock; opening Multi-view from a Lucid film and returning leaves it at its position and still advancing; a live/relay Lucid channel keeps today's pause-buffer behaviour.
- **Test:** device only; check `LiveTvLoadReport` for absence of a pause-buffer session.
- **Risk:** 🟡 medium (playback state). **Rollback:** guard is one condition.

### 1.9 Lucid TV: recover to the next source, then the next EPG item — M (4–6 h)

- **Source:** owner report (“not restarting / not changing to the next stream”); local audit
- **Files:** `LiveTvPlaybackController.kt`, `LucidTvRepository.kt` (read-only use of `advanceAfter`), new policy test
- **Local evidence:** on a stall, `checkStall()` reloads the **same** URL and calls `seekTo(resumeAt)` immediately after `prepare()`, before the timeline exists, so the seek is dropped. On a player error, `onPlayerError()` for Lucid shows “This Lucid TV film couldn't be played” and stops; it never tries the next resolved source or the next queue item. `fallbackUrls` is populated for Lucid but not used by the stall path.
- **Change:**
  1. Add `pendingVirtualResumeMs`; apply it from `onPlaybackStateChanged(STATE_READY)` / timeline changes, the same way `applyPendingVirtualStart()` handles the join offset.
  2. On a stall or error, try the next URL in `fallbackUrls` first, resuming at the saved position.
  3. After two failed sources (or three tries) on the same item, call `lucid.advanceAfter(channelKey, itemId)` and resolve the next tune immediately. The guide is republished by the repository.
  4. Show the “film couldn't be played” card only after `MAX_VIRTUAL_SKIPS` consecutive items fail; otherwise keep moving.
  5. Reset the failure counters once playback makes real progress.
- **Acceptance:** forced stall at 20:00 resumes near 20:00 from the backup source; with primary + backup dead, the next EPG item starts within ~10 s and the guide now/next moves with it; no infinite reload of one URL; errors still visible when the whole channel is dead.
- **Test:** device with a two-source resolved Lucid item (break the first URL, then both); `LiveTvLoadReport` shows the source switch and queue advance.
- **Risk:** 🟡 medium. **Rollback:** keep pending resume, disable auto-advance with a constant.

### 1.10 Lucid TV: one idempotent advance clock + watchdog — M (3–5 h)

- **Source:** owner report (“not changing to the next stream in the EPG”); local audit
- **Files:** `LiveTvPlaybackController.kt`, new `LucidAdvancePolicy.kt` + test
- **Local evidence:** the boundary is handled by a single `virtualAdvanceJob`; `STATE_ENDED` only advances early or when the timer is still running. If the job is cancelled, the player ends while `userPaused` is stuck, or `activeVirtual` is cleared without a replacement, nothing advances. There is no watchdog and no shared idempotent path.
- **Change:**
  1. Add one `advanceVirtualToNow(channel, slotEndMs, token)` used by the timer, the watchdog, `STATE_ENDED`, and the error path. It must be idempotent per token.
  2. Add a 5 s watchdog: if `activeVirtual != null`, the viewer is not paused, `now >= slotEndMs + 3_000`, and no resolve is in flight → advance.
  3. Do not clear `activeVirtual` until the next tune is committed; keep the old item's state through the resolve so a retry can use it.
  4. If `STATE_ENDED` arrives with no timer and no boundary, advance immediately to the item after the current one.
  5. Pure `LucidAdvancePolicy` decides due/paused/grace/token; unit-test it.
- **Acceptance:** cancelling the timer job in a debug build still advances within 5–8 s; a paused viewer never advances; resume joins the programme that is on now; no double advance when timer and `STATE_ENDED` race; guide and player stay in step.
- **Test:** `LucidAdvancePolicyTest` + device force-boundary test.
- **Risk:** 🟡 medium. **Rollback:** watchdog behind a constant; keep the old timer.

### 4.5 Lucid TV: prefetch the next slot and cache resolved sources — M–L (6–8 h)

- **Source:** owner report (“optimization”); local audit
- **Files:** `LiveTvPlaybackController.kt`, `LucidTvRepository.kt` (expose the next tune), new cache helper + test
- **Local evidence:** every Lucid boundary calls `resolveAndPlayVirtual()`, which fetches all addon streams (25 s timeout) and resolves up to 12 sources before the first frame. There is no prefetch and no resolved-URL cache for Lucid, so a normal film change can show black/“Loading…” for several seconds — exactly when the old item has already ended. The README's “next-two prefetch” is not wired into this path.
- **Change:**
  1. At T-60 s before `slotEndMs`, compute the next tune (`lucid.tune(channelKey, atMs = slotEnd + 1s)`) and resolve its sources in the background.
  2. Resolve the first few sources only (4–6, not 12) and let the rest resolve lazily if the primary fails — fewer provider connections and faster first frame.
  3. Cache primary + fallbacks for `(channelKey, itemId)` for 15 min, at most 8 entries; revalidate the primary with the existing `addonSourceReachable()` probe before use.
  4. On the boundary, use the cache; a miss falls back to today's resolve path.
  5. Cancel the prefetch on channel change, pause, or pool reload; never prefetch more than one slot ahead.
- **Acceptance:** a normal boundary reaches first frame in under ~2 s on the test box; logs show one source search per item, not two; no cache miss breaks playback; memory stays bounded.
- **Test:** device timing with `LiveTvLoadReport` timestamps; toggle airplane mode to exercise the miss path.
- **Risk:** 🟡 medium-high (playback). **Rollback:** constant disables prefetch; cache is additive.

### 4.6 Lucid TV: film-style player panel — S–M (3–4 h)

## 11. Risks & rollback

| Risk | Mitigation |
|---|---|
| Sync merge resurrects removed rows | Only carry rows whose addon is still installed; tests for uninstall |
| Multi-view backup switches to a lower-quality copy unexpectedly | Respect `autoBackupChannel`; show a notice; one switch per pane until manual refresh |
| Retry policy makes a temporarily busy provider feel “dead” | One delayed retry for 429/458; explicit OK to retry |
| Adaptive quality raises decoder load | Normal 4-pane stays 720p; low-RAM drops to 540p; measure first |
| TMDB alignment shifts normal shows | Exact season-set fast path; air-date fallback only when sets differ; tests |
| Subtitle label changes grouping | Label only changes the row title; language keys untouched |
| Lucid pause fix regresses live pause-buffer | Guard applies only to `activeVirtual` VOD (`!live && !relay`); live/relay tests stay unchanged |
| Lucid watchdog and timer both advance | One idempotent `advanceVirtualToNow()` with a token; `LucidAdvancePolicy` tests |
| Lucid prefetch hits debrid/provider limits | One slot ahead, at most 8 cache entries, reuse the existing reachability probe |
| Lucid failure path skips too aggressively | Advance only after two sources/three tries; reset on real progress; `LiveTvLoadReport` evidence |
| Stalker portal variants (endpoint, token format) | First version handles `/portal.php` + MAG handshake; report clear errors; keep M3U/Xtream untouched |
| Stalker link expiry | Re-resolve with `create_link` once on error; then use the normal reconnect ladder |
| Person search picks the wrong person | Exact-name match first, Acting department preferred; cache and show the name in the page header |
| Baseline profile run cannot reach Live TV (no playlists) | Journey marks degraded; generate with a seeded test playlist or accept partial coverage |

**Rollback:** every item is one commit. Phase branches are independent; no DB migrations; sync payload merge is the only shared-state change and is covered by tests.
